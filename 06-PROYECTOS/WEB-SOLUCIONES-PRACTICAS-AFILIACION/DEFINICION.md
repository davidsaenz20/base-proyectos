WEB DE SOLUCIONES PRÁCTICAS — AFILIACIÓN

1. IDENTIFICACIÓN

Nombre: Web de Soluciones Prácticas

Tipo: WEB DE AFILIACIÓN

Estado: Descubrimiento y validación inicial

Fecha de inicio: 2026-08-28

2. IDEA

Crear un sitio web de afiliación centrado en ayudar a personas que quieren realizar una actividad, empezar algo, prepararse para una situación o resolver una necesidad práctica.

La web no se organizará alrededor de un catálogo de productos, sino alrededor de problemas, necesidades e intenciones de usuario.

Ejemplo conceptual:

"QUIERO HACER X"

↓

"¿QUÉ NECESITO?"

↓

"¿CÓMO ME PREPARO?"

↓

"¿QUÉ DEBO LLEVAR / COMPRAR?"

↓

"GUÍA + CHECKLIST + SOLUCIÓN + PRODUCTOS"

3. PROBLEMA QUE RESUELVE

Muchas búsquedas de compra no empiezan con el nombre de un producto. Empiezan con una situación:

- quiero hacer senderismo;
- quiero acampar por primera vez;
- quiero empezar a pescar;
- quiero montar un huerto en un balcón pequeño;
- quiero preparar una mochila para una actividad;
- quiero saber qué necesito para una actividad concreta.

El usuario necesita descubrir qué necesita, qué opciones existen, qué errores evitar y qué productos tienen sentido.

4. PROPUESTA DE VALOR

Convertir una intención práctica en una solución completa y accionable.

Cada página debe responder, cuando corresponda:

1. qué quiere conseguir el usuario;
2. qué necesita saber;
3. qué necesita hacer;
4. qué materiales necesita;
5. qué productos puede utilizar;
6. qué alternativas existen;
7. qué errores debe evitar;
8. qué checklist puede seguir.

La afiliación debe formar parte natural de la solución y no sustituir el contenido útil.

5. ENFOQUE TEMÁTICO

La web podrá abarcar diferentes actividades y situaciones, pero todas deben compartir un propósito reconocible:

ayudar a las personas a prepararse para hacer algo o resolver una necesidad práctica.

No se pretende crear una web genérica sobre cualquier tema.

Las nuevas áreas deberán justificar su pertenencia a este propósito.

6. EJEMPLOS INICIALES DE ÁREAS

- senderismo y montaña;
- acampada y camping;
- pesca;
- jardinería urbana y huertos de balcón;
- supervivencia y preparación para actividades al aire libre.

Estas áreas son hipótesis iniciales y no constituyen todavía la arquitectura definitiva.

7. MODELO DE MONETIZACIÓN

Modelo principal previsto:

- marketing de afiliación de productos físicos;
- posibles programas de afiliación de servicios cuando encajen con una intención real.

No se asume una red de afiliación concreta.

La selección de programas se realizará mediante el módulo de afiliación correspondiente.

8. TIPO DE PÁGINAS PREVISTAS

Según la intención descubierta podrán existir:

- guías;
- checklists;
- páginas de soluciones;
- kits;
- comparativas;
- rankings;
- categorías;
- páginas de productos cuando estén justificadas;
- tutoriales;
- recursos interactivos cuando aporten valor.

No todas las intenciones deben generar una URL independiente.

9. MÓDULOS NECESARIOS

- "02-MODULOS/DESCUBRIMIENTO-DEMANDA-E-INTENCIONES.md"
- "02-MODULOS/GENERACION-ARQUITECTURA-URLS-POR-INTENCION.md"
- "02-MODULOS/MODULO-AFILIACION-AUTOMATIZADA.md"
- WordPress cuando se pase a construcción.
- Automatización/n8n cuando se diseñe la generación y actualización.
- Analítica cuando se prepare la medición.

Se comprobará durante el proyecto cuáles son realmente necesarios.

10. PRINCIPIO SEO

La arquitectura se basará en necesidades e intenciones reales, no en la multiplicación automática de keywords.

No se generarán grandes cantidades de URLs únicamente por combinaciones matemáticas.

Cada URL deberá justificar:

- intención;
- utilidad;
- diferenciación;
- contenido propio;
- encaje en la arquitectura;
- capacidad de mantenimiento.

11. CRITERIO DE ÉXITO DE LA FASE ACTUAL

La fase de descubrimiento será satisfactoria cuando podamos demostrar que el sistema es capaz de transformar una idea general en:

"DEMANDA → KEYWORDS/CONSULTAS → INTENCIONES → CLUSTERS → OPORTUNIDADES → PÁGINAS → URLS"

sin inventar métricas y sin crear páginas artificiales.

12. ALCANCE ACTUAL

Incluido

- definición de la propuesta;
- descubrimiento de demanda;
- investigación de intenciones;
- agrupación de consultas;
- arquitectura inicial;
- selección de tipos de página;
- validación del modelo.

No incluido todavía

- dominio;
- diseño visual definitivo;
- WordPress operativo;
- n8n operativo;
- APIs de afiliación;
- catálogo definitivo;
- publicación masiva;
- monetización validada.

13. RIESGOS INICIALES

Riesgo 1 — Amplitud excesiva

La web podría terminar siendo demasiado general.

Mitigación: mantener un propósito común y exigir justificación para cada nueva área.

Riesgo 2 — Generación masiva de URLs

Podrían generarse páginas por keywords sin suficiente diferenciación.

Mitigación: aplicar intención, SERP, agrupación, control de canibalización y validación antes de crear URLs.

Riesgo 3 — Contenido superficial automatizado

La automatización podría producir páginas repetitivas.

Mitigación: diseñar plantillas según intención y exigir datos, utilidad y diferenciación.

Riesgo 4 — Dependencia de afiliación

Una red o anunciante podría cambiar condiciones.

Mitigación: diseñar una arquitectura de fuentes de afiliación sustituibles.

14. ESTADO

La idea está en validación de demanda e intención.

Todavía no se considera validado el volumen potencial de negocio ni aprobada la arquitectura final.
