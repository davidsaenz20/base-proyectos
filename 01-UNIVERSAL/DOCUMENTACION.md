# DOCUMENTACIÓN UNIVERSAL

## Propósito

Definir las reglas generales para documentar correctamente cualquier proyecto.

## Principio

La documentación debe permitir comprender, recuperar, mantener y continuar un proyecto sin depender de la memoria de una conversación.

## Fuente de verdad

Cada información debe tener una ubicación principal.

- Estado → `00-CONTROL`
- Objetivo y alcance → documentación del proyecto
- Decisiones → `DECISIONES.md`
- Conocimiento universal → `01-UNIVERSAL`
- Conocimiento especializado → `02-MODULOS`
- Plantillas → `03-PLANTILLAS`
- Metodología específica → `04-TIPOS-PROYECTO`
- Ejemplos y pruebas → `05-FIXTURES`
- Información específica → `06-PROYECTOS`

## Registro

Las decisiones y cambios importantes deben quedar documentados.

No se debe depender exclusivamente del historial de conversación.

## Cambios

Cuando una decisión o estructura cambie:

1. registrar el cambio;
2. indicar el motivo;
3. identificar qué afecta;
4. actualizar la documentación vigente.

No se deben eliminar silenciosamente decisiones históricas importantes.

## Claridad

La documentación debe ser:

- clara;
- concreta;
- estructurada;
- actualizada;
- fácil de recuperar.

Debe evitarse documentación innecesariamente extensa.

## Recuperación

Una persona o agente que retome un proyecto debe poder determinar:

- dónde está el proyecto;
- qué está terminado;
- qué falta;
- qué decisiones están vigentes;
- qué problemas existen;
- cuál es el siguiente paso.

## Regla

La documentación existe para facilitar el trabajo, no para convertirse en trabajo innecesario.

Solo se documentará aquello que aporte valor futuro al proyecto o a otros proyectos.
