# PRINCIPIOS UNIVERSALES

## Propósito

Este archivo contiene los principios generales que deben respetarse durante el desarrollo de cualquier proyecto.

## Principios

### 1. Validar antes de construir

No se debe desarrollar una solución completa sin comprobar previamente que el problema existe y que la solución propuesta tiene sentido.

### 2. Separar problema y tecnología

Primero se define qué problema se quiere resolver.

Después se decide qué tecnología utilizar.

### 3. Simplicidad

Se debe utilizar la solución más sencilla que cumpla correctamente el objetivo.

### 4. Reutilización

Cuando una solución pueda convertirse en conocimiento, módulo o plantilla reutilizable, debe documentarse de forma independiente.

### 5. Trazabilidad

Las decisiones importantes deben quedar registradas.

### 6. Evidencias

Las afirmaciones importantes deben poder contrastarse mediante pruebas, datos, documentación o fuentes fiables cuando corresponda.

### 7. No improvisar

Cuando exista documentación previa relevante, debe consultarse antes de tomar nuevas decisiones.

### 8. Evolución controlada

Los cambios importantes deben quedar registrados y no deben eliminar silenciosamente decisiones anteriores.

### 9. Separación

El conocimiento universal, los módulos, las plantillas, los tipos de proyecto y los proyectos concretos deben mantenerse separados.

### 10. Construir solo lo necesario

No se debe crear documentación, código, automatizaciones o infraestructura que todavía no tengan una finalidad real.
