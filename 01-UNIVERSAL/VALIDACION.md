# VALIDACIÓN UNIVERSAL

## Propósito

Definir los criterios generales para comprobar que una solución funciona correctamente antes de considerarla terminada.

## Principio

Construir algo no significa que esté validado.

Toda funcionalidad relevante debe poder comprobarse mediante una prueba adecuada.

## Tipos de validación

### VALIDACIÓN FUNCIONAL

Comprueba que la solución hace aquello para lo que fue diseñada.

### VALIDACIÓN TÉCNICA

Comprueba que los componentes técnicos funcionan correctamente.

### VALIDACIÓN DE INTEGRACIONES

Comprueba que los diferentes servicios, APIs, sistemas o módulos se comunican correctamente.

### VALIDACIÓN DE DATOS

Comprueba que los datos se reciben, procesan, almacenan y devuelven correctamente.

### VALIDACIÓN DE ERRORES

Comprueba qué ocurre cuando algo falla.

### VALIDACIÓN DE SEGURIDAD

Comprueba que la solución no introduce riesgos innecesarios y que los mecanismos de protección funcionan.

### VALIDACIÓN DE NEGOCIO

Comprueba que la solución realmente resuelve el problema planteado y tiene sentido desde el punto de vista del negocio.

## CRITERIO DE FINALIZACIÓN

Una funcionalidad podrá considerarse validada cuando:

- se haya definido qué debe ocurrir;
- se haya realizado una prueba;
- el resultado observado coincida con el resultado esperado;
- cualquier error relevante haya sido registrado y resuelto o aceptado conscientemente.

## EVIDENCIAS

Cuando sea útil, las validaciones deberán conservar evidencias:

- resultados;
- capturas;
- registros;
- documentos;
- pruebas;
- enlaces;
- datos obtenidos.

## FALLO DE VALIDACIÓN

Cuando una prueba falle:

1. registrar el problema;
2. determinar su causa;
3. investigar si es necesario;
4. tomar una decisión;
5. modificar la solución;
6. repetir la validación.

## REGLA

No se debe marcar como completado aquello que no haya superado los criterios de validación definidos.
