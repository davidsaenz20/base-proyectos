# KADENCE — HEADER, FOOTER Y MENÚS

## Propósito

Documentar la configuración operativa del header, footer y menús utilizando WordPress y Kadence.

## 1. HEADER

Debe documentarse:

- estructura;
- logo;
- navegación;
- botón CTA;
- filas;
- alineación;
- altura;
- padding;
- colores;
- tipografía;
- sticky header;
- versión móvil;
- responsive.

### Ruta

La ruta exacta debe verificarse en la versión actual de Kadence antes de documentarla como definitiva.

Formato:

WordPress
→ Apariencia
→ Personalizar
→ [sección exacta]

### Regla

No utilizar CSS para una configuración que Kadence permita realizar mediante sus controles.

---

## 2. HEADER MÓVIL

Debe comprobarse específicamente:

- logo;
- menú hamburguesa;
- apertura/cierre;
- submenús;
- botón CTA;
- alineación;
- espaciado;
- tamaño;
- comportamiento al hacer scroll.

El resultado móvil debe validarse físicamente en una pantalla móvil.

---

## 3. FOOTER

Debe documentarse:

- número de columnas;
- widgets;
- enlaces;
- información de contacto;
- redes sociales;
- copyright;
- colores;
- tipografía;
- padding;
- responsive.

### Ruta

Verificar en:

WordPress
→ Apariencia
→ Personalizar
→ Footer

Registrar la ruta exacta y las opciones disponibles en la versión utilizada.

---

## 4. MENÚS

Debe documentarse:

- creación;
- edición;
- orden;
- enlaces;
- páginas;
- enlaces personalizados;
- categorías;
- submenús;
- menú principal;
- menú móvil;
- ubicación.

### Ruta habitual

WordPress
→ Apariencia
→ Menús

Si la instalación utiliza otra interfaz, registrar la ruta actual.

---

## 5. SUBMENÚS

Documentar:

- creación;
- niveles;
- comportamiento;
- hover;
- clic;
- responsive;
- móvil;
- estilos;
- flechas;
- accesibilidad.

No crear estructuras excesivamente profundas.

---

## 6. INTERLINKING

El menú es solamente una parte de la arquitectura de enlaces.

También deben utilizarse:

- enlaces contextuales;
- botones;
- breadcrumbs;
- bloques relacionados;
- enlaces entre páginas;
- enlaces desde contenido.

La estructura debe responder a la arquitectura SEO definida para cada proyecto.

---

## 7. CTA DEL HEADER

Cuando exista un botón principal en el header:

Documentar:

- texto;
- URL;
- estilo;
- tamaño;
- colores;
- hover;
- responsive;
- comportamiento móvil.

Debe utilizar el estilo global de botones cuando sea posible.

---

## 8. COHERENCIA VISUAL

Header y footer deben compartir:

- paleta;
- tipografía;
- espaciado;
- estilo de botones;
- radios;
- iconografía.

No deben diseñarse como elementos independientes.

---

## 9. VALIDACIÓN

Comprobar:

### Escritorio

- logo;
- menú;
- submenús;
- CTA;
- alineación.

### Tablet

- distribución;
- tamaños;
- navegación.

### Móvil

- menú hamburguesa;
- submenús;
- CTA;
- logo;
- espaciado.

11. REGLA OPERATIVA

Cuando el usuario necesite realizar una modificación, nunca indicar únicamente:

> "Configura el header."



Debe indicarse:

OBJETIVO

Qué queremos conseguir.

RUTA

Dónde debe entrar.

CAMBIO

Qué debe modificar.

VALOR

Qué debe introducir.

VERIFICACIÓN

Qué debe comprobar después.


---

Estado

Este documento es una base operativa inicial.

Las rutas y opciones concretas deben verificarse con la documentación oficial actual de Kadence antes de convertirse en instrucciones definitivas.
