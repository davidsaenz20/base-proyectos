# KADENCE — FUENTES OFICIALES

## Propósito

Registrar las fuentes utilizadas para mantener actualizada la Knowledge Base operativa de Kadence.

La documentación debe priorizar siempre fuentes oficiales y actualizadas.

---

# 1. KADENCE

Fuente principal:

https://www.kadencewp.com/

Utilizar para:

- documentación del tema;
- configuración;
- funcionalidades;
- tutoriales;
- cambios de producto;
- compatibilidad.

---

# 2. DOCUMENTACIÓN DE KADENCE

Fuente:

https://www.kadencewp.com/help-center/

Prioridad máxima para determinar:

- dónde se encuentra una configuración;
- cómo funciona una opción;
- qué funcionalidades están disponibles;
- diferencias entre versiones;
- procedimientos de configuración.

---

# 3. KADENCE BLOCKS

Fuente:

https://www.kadencewp.com/kadence-blocks/

Utilizar para documentar:

- bloques;
- opciones;
- layouts;
- componentes;
- funcionalidades gratuitas;
- funcionalidades Premium.

---

# 4. DOCUMENTACIÓN DE KADENCE BLOCKS

Fuente:

https://www.kadencewp.com/help-center/docs/kadence-blocks/

Utilizar para determinar la configuración exacta de los bloques.

---

# 5. WORDPRESS

Fuente oficial:

https://wordpress.org/documentation/

Utilizar para:

- funcionamiento del editor;
- páginas;
- entradas;
- menús;
- medios;
- usuarios;
- ajustes;
- bloques;
- patrones.

---

# 6. WORDPRESS BLOCK EDITOR

Fuente:

https://wordpress.org/documentation/article/wordpress-editor/

Utilizar para documentar funcionalidades propias de Gutenberg que no pertenecen específicamente a Kadence.

---

# 7. WORDPRESS BLOCK DIRECTORY

Fuente:

https://wordpress.org/plugins/

Utilizar para investigar plugins gratuitos cuando WordPress y Kadence no puedan resolver una necesidad concreta.

---

# 8. WORDPRESS THEME DIRECTORY

Fuente:

https://wordpress.org/themes/

Utilizar para verificar:

- versión del tema;
- instalaciones;
- actualizaciones;
- compatibilidad;
- información pública del tema.

---

# 9. REGLA DE FUENTES

Prioridad:

1. documentación oficial de Kadence;
2. documentación oficial de WordPress;
3. documentación oficial del plugin correspondiente;
4. fuentes técnicas secundarias fiables;
5. foros/comunidad únicamente como apoyo.

No utilizar una fuente secundaria para afirmar una funcionalidad cuando pueda verificarse mediante documentación oficial.

---

# 10. VERIFICACIÓN DE FUNCIONALIDADES

Antes de documentar una instrucción concreta:

1. localizar la funcionalidad;
2. comprobar la documentación;
3. comprobar la versión relevante;
4. comprobar si es gratuita o Premium;
5. comprobar la ruta de configuración;
6. registrar la fuente.

---

# 11. FUNCIONES PREMIUM

Si una documentación indica que una funcionalidad requiere:

- Kadence Pro;
- Kadence Blocks Pro;
- extensión Premium;
- plugin Premium;

debe marcarse claramente.

Formato:

```text
FUNCIÓN:
[nombre]

ESTADO:
PREMIUM

ALTERNATIVA GRATUITA:
[solución]

VIABLE:
Sí / No

No asumir que una funcionalidad Premium puede utilizarse en la metodología gratuita.


---

12. VERSIONES

Cuando una configuración dependa de una versión concreta, registrar:

Tema:
Kadence [versión]

WordPress:
[versión]

Kadence Blocks:
[versión]

Fecha de comprobación:
[fecha]


---

13. CAMBIOS DE INTERFAZ

Si una ruta documentada deja de coincidir con la interfaz actual:

1. comprobar documentación oficial;


2. localizar la nueva ruta;


3. actualizar la Knowledge Base;


4. eliminar o marcar la ruta anterior como obsoleta.




---

14. INFORMACIÓN NO VERIFICADA

No convertir una suposición en documentación.

Si no se puede verificar una funcionalidad:

ESTADO:
NO VERIFICADO

Debe investigarse antes de utilizarla como instrucción operativa definitiva.


---

15. REGISTRO DE ACTUALIZACIONES

Cada actualización importante de esta Knowledge Base debe registrar:

fecha;

versión;

documento afectado;

cambio realizado;

fuente utilizada.


Ejemplo:

Fecha:
[fecha]

Versión:
[versión]

Documento:
[nombre]

Cambio:
[descripción]

Fuente:
[URL]


---

16. PRINCIPIO FINAL

La Knowledge Base debe mantenerse basada en información verificable.

La documentación oficial prevalece sobre:

memoria del sistema;

tutoriales antiguos;

capturas antiguas;

comentarios de usuarios;

artículos desactualizados.


El objetivo es que las instrucciones entregadas al usuario sean:

actuales + verificables + reproducibles + gratuitas cuando así lo exija el proyecto.
