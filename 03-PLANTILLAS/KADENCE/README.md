# KADENCE — KNOWLEDGE BASE OFICIAL-OPERATIVA

## Propósito

Esta carpeta contiene la base de conocimiento operativa para trabajar con el tema Kadence y, cuando corresponda, Kadence Blocks dentro de WordPress.

Su finalidad no es almacenar únicamente documentación teórica.

Debe permitir transformar cualquier requisito de diseño, estructura o funcionalidad de una web en instrucciones prácticas y verificables para ejecutarlo dentro de WordPress.

---

## Objetivo

Utilizar Kadence como tema estándar de construcción web mientras mantenga una relación adecuada entre:

- funcionalidades gratuitas;
- facilidad de configuración;
- calidad visual;
- flexibilidad;
- rendimiento;
- compatibilidad con WordPress;
- editor de bloques;
- responsive;
- reutilización;
- automatización;
- documentación;
- mantenimiento.

No se presupone la utilización de funcionalidades Premium.

Cuando una solución requiera una funcionalidad Premium, debe indicarse expresamente y buscarse primero una alternativa gratuita viable.

---

## Principio operativo

La Knowledge Base debe responder siempre a esta pregunta:

> ¿Cómo consigo exactamente este resultado en WordPress utilizando Kadence?

La respuesta debe priorizar, en este orden:

1. Configuración nativa de WordPress.
2. Configuración nativa de Kadence.
3. Kadence Blocks gratuito.
4. Plugins gratuitos compatibles.
5. CSS.
6. Código personalizado únicamente cuando sea necesario.

No debe utilizarse CSS para solucionar algo que pueda configurarse correctamente mediante las opciones disponibles del tema o los bloques.

---

## Forma de utilizar esta documentación

Cuando durante un proyecto se defina un requisito, el sistema debe:

1. Identificar qué resultado se quiere conseguir.
2. Buscar si Kadence dispone de una función específica.
3. Identificar la ruta exacta dentro de WordPress.
4. Determinar qué opción debe modificarse.
5. Indicar el valor recomendado.
6. Comprobar si afecta a escritorio, tablet y móvil.
7. Indicar si requiere CSS, plugin o código.
8. Verificar el resultado.
9. Registrar cualquier solución nueva descubierta durante el proyecto.

---

## Regla de verificación

La documentación no debe inventar rutas, botones, opciones ni funcionalidades.

Cuando una instrucción dependa de una versión concreta de Kadence o WordPress, debe comprobarse mediante documentación oficial actualizada o mediante una fuente técnica fiable.

Si una opción no puede localizarse con suficiente seguridad, debe indicarse:

> OPCIÓN NO VERIFICADA

y continuar investigando antes de hacer que el usuario pierda tiempo buscándola manualmente.

## Regla de mejora continua

Cada vez que durante un proyecto se descubra una configuración útil, una ruta concreta, una limitación o una solución que pueda reutilizarse en otros proyectos, debe evaluarse su incorporación a esta Knowledge Base.

El objetivo es que el conocimiento acumulado reduzca progresivamente el tiempo necesario para construir nuevos proyectos.

---

## Relación con la metodología universal

Esta Knowledge Base no sustituye a la metodología universal del proyecto base.

La metodología universal determina:

- qué hay que construir;
- por qué hay que construirlo;
- en qué orden;
- cómo validarlo;
- cuándo tomar decisiones;
- cuándo continuar o detener el proyecto.

Esta Knowledge Base determina principalmente:

> cómo ejecutar técnicamente determinadas partes de la construcción utilizando Kadence.

---

## Criterio de prioridad

La prioridad será siempre:

**resultado profesional + simplicidad + gratuidad + reutilización + estabilidad.**

No se utilizará una función únicamente porque exista.

Se elegirá la solución que permita conseguir el resultado requerido con el menor nivel razonable de complejidad y dependencia.
