# TIPO DE PROYECTO SAAS

## Propósito

Definir la metodología específica para proyectos de software ofrecido como servicio.

## OBJETIVO

Crear un servicio de software accesible online, mantenible, escalable y capaz de atender a múltiples clientes.

## CARACTERÍSTICAS

Puede incluir:

- cuentas de usuario;
- múltiples clientes;
- panel de administración;
- suscripciones;
- pagos;
- gestión de permisos;
- datos separados por cliente;
- APIs;
- automatizaciones;
- integraciones externas.

## MÓDULOS HABITUALES

Según las necesidades:

- web;
- base de datos;
- APIs;
- autenticación;
- seguridad;
- automatización;
- IA;
- notificaciones;
- email;
- observabilidad;
- archivos.

## MULTIUSUARIO

Definir:

- usuarios;
- clientes;
- organizaciones;
- roles;
- permisos;
- aislamiento de datos.

## MODELO DE NEGOCIO

Definir:

- precio;
- planes;
- límites;
- periodo de facturación;
- prueba;
- cancelación;
- servicios incluidos.

## DATOS

Los datos de diferentes clientes deben mantenerse correctamente aislados.

Definir:

- propiedad;
- acceso;
- retención;
- eliminación;
- backups.

## ESCALABILIDAD

Evaluar:

- número de usuarios;
- clientes;
- operaciones;
- almacenamiento;
- tráfico;
- concurrencia;
- costes.

## SEGURIDAD

Controlar especialmente:

- autenticación;
- autorización;
- aislamiento entre clientes;
- credenciales;
- datos personales;
- APIs.

## MONITORIZACIÓN

Supervisar:

- disponibilidad;
- errores;
- rendimiento;
- consumo;
- operaciones críticas.

## VALIDACIÓN

Comprobar:

- registro;
- acceso;
- funciones principales;
- permisos;
- aislamiento de datos;
- facturación;
- errores;
- recuperación.

## PRINCIPIO

La arquitectura debe permitir crecer sin introducir complejidad innecesaria.
