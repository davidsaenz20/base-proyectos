# TIPO DE PROYECTO PORTAL

## Propósito

Definir la metodología específica para proyectos que reúnen diferentes funcionalidades, usuarios, contenidos o servicios dentro de una misma plataforma.

## OBJETIVO

Crear un punto central de acceso a información, servicios o herramientas para uno o varios tipos de usuario.

## CARACTERÍSTICAS

Puede incluir:

- registro de usuarios;
- perfiles;
- paneles;
- contenidos;
- formularios;
- búsquedas;
- servicios;
- documentos;
- notificaciones;
- integraciones externas.

## MÓDULOS HABITUALES

Según las necesidades:

- web;
- base de datos;
- APIs;
- autenticación;
- seguridad;
- archivos;
- notificaciones;
- email;
- automatización;
- IA;
- observabilidad.

## USUARIOS

Definir:

- tipos de usuario;
- roles;
- permisos;
- funcionalidades disponibles para cada perfil.

## ARQUITECTURA

Separar claramente:

- área pública;
- área privada;
- gestión de usuarios;
- datos;
- servicios;
- integraciones.

## DATOS

Definir:

- entidades;
- relaciones;
- propiedad;
- permisos;
- almacenamiento;
- retención.

## SEGURIDAD

Controlar especialmente:

- autenticación;
- autorización;
- sesiones;
- datos personales;
- documentos;
- permisos entre usuarios.

## ESCALABILIDAD

Evaluar:

- usuarios;
- tráfico;
- operaciones;
- almacenamiento;
- concurrencia;
- costes.

## VALIDACIÓN

Comprobar cada flujo de usuario y verificar que ningún usuario pueda acceder a información o funciones que no le correspondan.

## PRINCIPIO

La complejidad del portal debe estar justificada por las necesidades reales de los usuarios.

## ESTADO

**Estado:** Base inicial

**Versión:** 1.0
